Purchase Order Automation

Why this module

When goods arrive as ordered and the vendor is paid on receipt, the procure-to-pay chain is the same five clicks every time. This module does them for you, safely.

In standard Odoo 18

  • Confirm Order only creates the receipt; someone still has to open it and click Validate.
  • The vendor bill is created by hand with Create Bill, then needs a Bill Date before it can be confirmed.
  • Payment is a separate Register Payment step on every bill.
  • The Create Vendor Bills list action only creates draft bills; it does not receive goods, post or pay.
  • In a multi-record action, one error stops the whole selection.
  • Nothing tells you which orders were left half-done or why.

With this module

  • Confirming the order validates the receipt with the ordered quantities.
  • The bill is created and dated automatically (today, receipt date or order date) and can be posted right away.
  • Scenario C registers the payment on your bank or cash journal and reconciles the bill.
  • The batch wizard runs the whole chain on RFQs and orders alike, with per-run overrides.
  • Each order runs in its own savepoint: a failing order is rolled back, the others are completed.
  • Failures get a chatter note, a red banner, an Automation Status and a search filter.

How it works

Four steps from a fresh install to automated purchasing.

1
Enable
Tick Purchase Automation in Purchase settings and pick scenario A, B or C.
2
Configure
Choose the bill date rule, backorder policy, error policy and the payment journal.
3
Run
Click Confirm Order, or select orders and use one of the two Actions menu entries.
4
Review
Read the result screen; fix failed orders from the Automation Failed filter and run again.

Features

All screenshots were taken on Odoo 18 with the standard demo data (vendors Wood Corner, Gemini Furniture, Azure Interior, Ready Mat) and the generic chart of accounts.

Menus

Where to find everything

Settings live in Purchase › Configuration › Settings › Procurement Automation. Select orders in Purchase › Orders › Requests for Quotation or Purchase Orders and open the Actions menu (⚙): Run Procurement Automation... opens the batch wizard, Run Procurement Automation (Company Defaults) runs immediately with the company settings. Both lists get an Automation Status column.

Feature 1

One settings block per company

Purchase Automation is the master switch. Pick the Scenario, the Bill Date rule (Today, Receipt Validation Date or Order Date) and the Backorders policy. Run on PO Confirmation hooks the automation on the confirm/approve buttons, and On Confirmation Error decides whether a failure keeps the order confirmed (and logs it) or blocks the confirmation. Restrict to Purchase Managers limits who triggers it. Journals sets an optional Vendor Bill Journal and the Payment Journal / Payment Method for scenario C.

Feature 2

Confirm Order does the rest

With Run on PO Confirmation on, confirming P00006 (scenario B) validated the receipt, created the bill in Vendor Bills and posted it. Received and Billed match the ordered quantities and the chatter lists every step. With two-step approval, the automation starts when the manager clicks Approve Order.

Feature 3

Batch wizard with per-run overrides

Run Procurement Automation... works on RFQs and confirmed orders. Change the Scenario and Backorders policy for this run, turn on Generate Lot/Serial Numbers, and override Receive In Warehouse, Bill Journal, Bill Date, Payment Journal, Payment Method and Payment Date. Empty overrides fall back to the company settings, which the run never changes.

Feature 4

A result screen you can act on

The wizard ends with three counters – Processed, Nothing to do, Failed – and the exact error per failed order. Here P00002, P00003 and P00007 went all the way to payment while P00001, which holds a lot-tracked Drawer without lot numbers, was rolled back. Open Failed Orders lists them.

Feature 5

Scenario C: received, billed and paid

For P00002 the chatter shows the full chain: order confirmed, receipt validated, bill created, bill posted, payment registered. The bill carries the PAID ribbon and an Amount Due of zero; the payment was made through Odoo’s own Register Payment wizard on the configured bank journal.

Feature 6

Failures are visible, explained and safe

A failed order gets a warning banner with the step and the reason, a chatter note that confirms everything of that run was rolled back, and the Failed status. P00001 is still an RFQ with no receipt, bill or payment – nothing half-done to clean up.

The Automation Failed and Automated filters are added to the purchase search view.
Feature 7

Automation Status next to Billing Status

The Purchase Orders list shows Processed / Failed badges beside Odoo’s Billing Status, so you see at a glance that every automated order is Fully Billed while the other demo orders still show Nothing to Bill. The form also shows the Last Automation Run in Other Information.

Feature 8

Fully translated to Arabic

All 137 terms – settings, wizard, actions, statuses, chatter notes and error messages – ship with an Arabic translation, displayed right-to-left. A .pot template is included for other languages.

The three scenarios

Every scenario confirms the order and validates its receipts; they differ in how far the vendor bill goes.

ScenarioVendor billPayment
A – Draft BillDraft–
B – Posted BillPosted–
C – Posted Bill, PaymentPostedPaid / In Payment
Resume, don’t duplicate: running the automation again picks up where it stopped. An order processed with scenario A and later run with scenario C gets its existing draft bill posted and paid – no second bill. A completed order is reported as Nothing to do. Only bills created by the automation are ever posted or paid; bills entered by hand are left alone.

Built for real-world corner cases

Every case below is handled in the code and most are covered by a test.

Lot and serial numbers
Tracked products stop the order with a clear message, unless the wizard’s Generate Lot/Serial Numbers creates unique names like P00001-FURN-8855-0001.
Services
Service lines with manual received quantities are marked received, so “billed on received quantities” does not block the bill.
Backorders
Choose to cancel remainders or keep them as backorders. Backorders left from an earlier manual receipt are validated and billed in full.
Two-step approval
Orders waiting in To Approve start the automation when a manager approves them; the batch reports orders the user may not approve as failed.
Manual steps on receipts
If a receipt still needs a manual step after validation (e.g. Enterprise quality checks), the order fails cleanly instead of being forced.
Lock dates
Bills dated in a locked period follow Odoo’s own rule: posted with the accounting date moved after the lock date.
Two users, same order
Each order is row-locked while it runs; a second run reports that the order is being processed instead of doubling it.
Multi-company batches
Each order follows its own company’s settings. Warehouse and journal overrides are refused when the selection spans companies.
Missing configuration
Scenario C without a payment journal, a journal of another company, a cancelled order: each is reported or skipped, never half-applied.

Security

No new groups: the module uses Odoo’s purchase groups and runs every step with the user’s own access rights.

WhoCan
Purchase / UserTriggers the automation by confirming orders and uses both list actions and the wizard, unless the company restricts it to managers.
Purchase / AdministratorEdits the Procurement Automation settings and is always allowed to run the automation.
Restrict to Purchase Managers onOther users confirm orders the standard way (no automation) and are refused by the list actions.
Inventory & Invoicing rightsReceipts, bills and payments are created as the current user, so the usual Inventory and Invoicing permissions still apply.
Multi-companySettings are stored per company; journals and warehouses must belong to the order’s company.
